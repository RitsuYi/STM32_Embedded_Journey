# PID 速度控制模块说明

## 1. 这个模块是做什么的？

这个 PID 模块负责让小车的四个电机尽量按照指定转速运行。

可以把它想象成司机控制车速：

- `Target` 是希望达到的车速，例如 200 RPM。
- `Actual` 是编码器测到的真实车速，例如 170 RPM。
- 两者相差 30 RPM，PID 会根据这个差距计算应该给电机多大的 PWM。
- 下一次再读取转速、再修正，如此循环，小车速度就会逐渐接近目标值。

在当前工程中，速度 PID 每 **20 ms** 计算一次。四个电机分别拥有自己的 `PID_t`，所以每个轮子都能根据自己的实际转速独立调整输出。

## 2. PID 三部分的直观理解

PID 是比例（P）、积分（I）、微分（D）三个部分的简称。

### P：看到差距，马上纠正

当前程序的比例项为：

```text
POut = Kp × (目标转速 - 实际转速)
```

误差越大，纠正力度越大。`Kp` 太小，电机追得慢；`Kp` 太大，转速容易来回摆动。

### I：长期没追上，就继续加力

当前程序每次把误差累加到积分项：

```text
IOut = IOut + Ki × 当前误差
```

积分可以消除“总是差一点”的问题。不过积分积得太多会造成超调，所以程序把 `IOut` 限制在 `IOutMin` 到 `IOutMax` 之间。

### D：变化太快，就提前刹车

当前程序不是对误差做微分，而是观察实际转速的变化：

```text
DOut = -Kd × (本次实际转速 - 上次实际转速)
```

这样做能减少目标值突然变化带来的“微分冲击”。编码器转速可能有抖动，因此当前默认 `Kd` 为 0，也就是暂时没有启用微分作用。

最终结果是：

```text
Out = POut + IOut + DOut + 方向对应的死区补偿
```

最后，`Out` 还会被限制在 `OutMin` 到 `OutMax` 之间，防止 PWM 命令超出允许范围。

## 3. 当前程序是怎样运行的？

主要数据流如下：

```text
目标转速 ─────┐
              ├─> PID_Calculate() ─> 带方向的 PWM 命令 ─> 电机驱动
编码器实际转速 ┘          ↑
                         │
                  每 20 ms 执行一次
```

上电初始化过程：

1. `Motor_Init()` 调用 `PID_LoadSpeedConfig()`，从 `BoardConfig.h` 载入默认参数。
2. 程序为四个电机分别调用 `PID_Init()`，清空各自状态。
3. 程序调用 `PID_ApplySpeedConfig()`，让四个控制器使用同一套默认参数。
4. 运行时，`Motor_ControlTask()` 读取各编码器转速。
5. 每个电机调用一次 `PID_Calculate()`，得到带正负方向的 PWM 命令。
6. `Motor_ApplyDriveCommand()` 把命令交给电机驱动。

这种结构是“参数共用，状态独立”：四个轮子使用相同的 Kp、Ki、Kd，但各自记录自己的误差和积分，不会互相串数据。

## 4. 当前默认参数

默认参数在 `UserConfig/BoardConfig.h` 中：

| 参数 | 当前值 | 初学者可以怎样理解 |
| --- | ---: | --- |
| 控制周期 | 20 ms | 每秒计算 50 次 |
| `Kp` | 0.10 | 当前误差带来的立即纠正力度 |
| `Ki` | 0.05 | 每轮累计误差的力度 |
| `Kd` | 0.00 | 当前没有使用微分调节 |
| 积分限幅 | 1200 | 防止积分无限累加 |
| 输出限幅 | `BOARD_PWM_MAX_DUTY` | PID 输出不能超过 PWM 硬件上限 |
| 输出偏置 | 0 | 当前没有启用电机死区补偿 |

注意：当前算法没有把 20 ms 换算成秒参与公式，因此 `Ki`、`Kd` 的实际效果和控制周期有关。以后如果把控制周期从 20 ms 改成其他值，原来的参数通常需要重新调整。

## 5. 两个结构体分别保存什么？

### `PID_t`：某一个电机的完整控制器

它保存三类数据：

- 输入和输出：`Target`、`Actual`、`Out`。
- 参数和限制：`Kp`、`Ki`、`Kd`、积分限幅、输出限幅、死区补偿。
- 历史状态：上次实际值、误差、累计积分等。

因为历史状态不能混用，所以四个电机必须各有一个 `PID_t`。

### `PID_SpeedConfig_t`：四个速度环共用的参数表

它只保存 Kp、Ki、Kd 和限幅，不保存运行历史。蓝牙修改的是这份共用配置，然后由 `Motor_RefreshPidProfiles()` 同步给四个电机。

## 6. 对外函数怎么用？

| 函数 | 作用 | 什么时候调用 |
| --- | --- | --- |
| `PID_LoadSpeedConfig()` | 从板级配置读取默认参数 | 系统上电初始化时 |
| `PID_GetSpeedConfig()` | 读取当前共用参数 | OLED 显示、蓝牙回传时 |
| `PID_SetSpeedTunings()` | 修改 Kp、Ki、Kd | 在线调参时 |
| `PID_SetSpeedLimits()` | 修改积分和输出限幅 | 在线调参或安全限制变化时 |
| `PID_Init()` | 清空参数和状态 | PID 实例第一次使用前 |
| `PID_Reset()` | 只清运行状态，保留参数 | 停车、切换模式、重新起步时 |
| `PID_ApplySpeedConfig()` | 把共用配置复制给某个实例 | 初始化后或参数变化后 |
| `PID_Update()` | 用结构体里已有的输入算一次 | 需要分开写输入和计算时 |
| `PID_Calculate()` | 写入目标与反馈，计算并返回输出 | 当前电机控制任务中 |

最小使用流程如下：

```c
PID_t speedPid;
float pwmOutput;

PID_LoadSpeedConfig();
PID_Init(&speedPid);
PID_ApplySpeedConfig(&speedPid);

/* 此后每个固定控制周期调用一次。 */
pwmOutput = PID_Calculate(&speedPid, targetRpm, actualRpm);
```

如果调用 `PID_SetSpeedTunings()` 或 `PID_SetSpeedLimits()` 修改参数，已有的 `PID_t` 不会自动变化。当前小车程序会紧接着调用 `Motor_RefreshPidProfiles()`，把新参数同步给四个电机。

## 7. 当前代码做得好的地方

1. **每个电机状态独立。** 四个轮子的积分和历史数据互不干扰，这是多电机闭环控制必须做到的。
2. **参数与运行状态分开。** 共用配置便于统一调参，每个实例仍保存独立状态，结构清楚。
3. **有积分限幅和总输出限幅。** 能降低积分累积过大、PWM 超过硬件能力等风险。
4. **微分使用实际值变化量。** 目标转速突然变化时，不容易产生很大的瞬间微分输出。
5. **重置和初始化用途分开。** `PID_Reset()` 会保留调好的参数，停车后重新运行不必重新装载参数。
6. **有空指针保护。** 调用者误传空指针时会安全返回，减少程序崩溃的可能。
7. **支持在线调参。** 蓝牙可以读取或修改速度环参数，OLED 也能读取配置，调试比反复烧录固件方便。
8. **限幅参数会做基本整理。** 负的限幅会转成正数，输出限幅过小时也有最低值保护。

## 8. 可以怎样优化？

下面按建议优先级排列。现有代码已经可以使用，不需要一次把所有优化都做完。

### 优先级 1：把控制周期写进公式

标准离散 PID 通常会使用时间间隔 `dt`：

```text
IOut = IOut + Ki × 误差 × dt
DOut = -Kd × 实际值变化量 ÷ dt
```

这样即使控制周期改变，参数含义也比较稳定。当前算法没有显式使用 `dt`，所以 0.05 的 `Ki` 实际是“每 20 ms 累加一次”。如果采用这个优化，需要重新整定已有参数，不能只改公式。

### 优先级 2：增强抗积分饱和

现在的做法是直接夹住积分项，简单有效。还可以进一步判断：当最终输出已经到达上限，而且误差还想让输出继续增大时，暂时停止积分；只有误差方向有助于退出饱和时才继续积分。这样大幅加速后再减速，通常会恢复得更快。

### 优先级 3：给微分项加低通滤波

编码器测速会有跳动，微分又会放大这种跳动。如果以后把 `Kd` 调到非零，建议先对实际速度或微分项做简单低通滤波，否则 PWM 可能抖动。

### 优先级 4：处理微分第一次计算的突变

`PID_Reset()` 会把 `Actual1` 清零。如果重置后电机仍在转，并且 `Kd` 不为零，第一次计算会把当前速度和 0 比较，可能出现瞬间输出变化。可以增加“第一次更新”标志，第一次只记录实际值，不计算 D 项。

### 优先级 5：让接口和单位更明确

- 可以统一成员命名风格，例如全部使用 `target`、`actual` 这样的形式。
- 可以在名称或注释中明确 RPM、PWM 等单位。
- `Error1` 目前只保存但没有参与计算；如果以后仍不使用，可以删除以节省少量内存，或者用于调试与其他微分算法。
- `outputOffset` 已经进入结构体和计算过程，但当前没有公开的设置函数；若电机存在明显死区，可以补充设置接口。

### 优先级 6：加强参数合法性检查

现在已经会整理限幅的正负值。后续还可以限制 Kp、Ki、Kd 的合理范围，并拒绝 `NaN`、无穷大等异常浮点数，防止错误的蓝牙数据破坏控制结果。

### 优先级 7：降低模块对芯片头文件的依赖

`PID.h` 当前包含 `stm32f4xx.h`，但头文件自身只使用了标准 C 的 `float` 和指针。以后可以考虑移除这个依赖，让 PID 算法更容易移植到其他单片机或电脑测试程序中。

## 9. 初学者调参建议

调参时应把小车架空或放在宽敞区域，并保留输出限幅，避免突然冲出。

1. 先设 `Ki = 0`、`Kd = 0`，只调 `Kp`。
2. 从较小的 `Kp` 开始逐步增加，直到响应够快但还没有明显来回振荡。
3. 再慢慢增加 `Ki`，让实际速度能够消除长期偏差。
4. 如果超调或抖动明显，先适当减小 `Kp`、`Ki`。只有确有需要时再加入少量 `Kd`。
5. 每次只改一个参数，并记录“目标转速、实际转速、PWM 输出”的曲线，否则很难判断是哪一个参数产生了效果。
6. 正转和反转、低速和高速、空载和落地都要测试，因为电机特性会不同。

蓝牙调参后，重点观察工程已有的绘图数据：目标转速、实际转速和 PWM 输出。如果实际速度快速接近目标、没有持续振荡，而且 PWM 没有长时间顶在上限，通常说明参数方向是合理的。

## 10. 阅读代码的推荐顺序

建议初学者按下面的顺序阅读：

1. `App/PID.h`：先认识数据和接口。
2. `App/PID.c` 中的 `PID_Calculate()`：看入口函数。
3. `App/PID.c` 中的 `PID_Update()`：看 P、I、D 的实际公式。
4. `Hardware/Motor.c` 中的 `Motor_ControlTask()`：看 PID 怎样连接编码器和 PWM。
5. `UserConfig/BoardConfig.h`：看默认参数与 20 ms 控制周期。
6. `App/AppTask.c`：看蓝牙怎样读取、修改并同步 PID 参数。
