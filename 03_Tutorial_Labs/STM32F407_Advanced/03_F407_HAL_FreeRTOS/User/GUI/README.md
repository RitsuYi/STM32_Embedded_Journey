## OLED性能显示与本轮对照

- `FPS:000.0`：最近约1秒内成功发送的LVGL刷新次数，包含空闲时间；整屏10个DMA块合成的一次刷新只算1帧，失败/无像素刷新不算，静止时可为0或仅剩时钟刷新。它不是面板内部扫描率；短暂180ms动画受窗口内空闲影响，比较时持续滑动约2秒。
- `MS:0000 BLK:000`：最近一次成功刷新的耗时（毫秒，含布局/绘图与末DMA等待）及DMA块数；`ERR`显示传输错误累计最低6位。最后耗时会保留，局部时钟刷新也可能更新它，不能单看停止后某个数值认定整页耗时。
- GUI只发布数字，OLED任务在短临界区复制36B统计；排版/I²C均在临界区外。统计区每秒最多发送上方32像素/512B，底部按键提示仅变化时更新，不再每轮整屏发送1024B；原100kHz、共享锁/恢复和按键消抖保持。新增`last_frame_wait_ms`/`last_frame_pack_ms`供调试器看Finish等待及换序墙钟毫秒，不新增OLED行；不是DMA总忙时长或CPU周期，不能直接推CPU占用。
- 旧OLED版三组实测10.3/10.5/10.4FPS、89/88/91ms、31块、ERR0保持历史；20/32行版分别获约再提高3帧的用户反馈，无新绝对数，不倒推16.4FPS。相同历史body的软件8/16/20/32行对照为31/16/13/8块，均229272B且逐像素一致；A版未减少这批整块历史像素，不承诺全场景30FPS。

## 二维皮肤和数据边界

参考图布局和二维圆环保留。蓝色0x98CBFA、正文0x78899B，底色0xFAF9F6略暖；正文12px、标题14px、主标题/质检数字16px、主尺寸数字26px，官方原尺寸取字。底部为36px高完整胶囊（Y276～311，下方留阴影，触摸到Y319），独立16px轻轮廓盾牌/直尺/齿轮，播放/停止略小，16px图标+8px间距+实际文字作为一组居中；保留四标题的完整16px图标。Wi-Fi已连接蓝色，未连接灰色带斜杠，竖线分隔时间。按钮按下/禁用遮罩沿用胶囊圆角，键盘特殊键样式保持。见`fonts/README.md`和`measurement/ui_icons.h`。

`assets/ui_skin.c`使用960B解码行，Flash中14种预计算抖色渐变覆盖292/278×232背景、卡片、页脚按钮和117×8蓝色进度条；可随机解码相交行/列，不展开整图RAM。进度条按原0xA0D8FF→0x98CBFA水平渐变离线量化，按进度裁剪同一像素图并保留圆角，运行时不重新计算渐变。`tools/generate_ui_perf_tables.py`只需Python标准库，主题改变后用它重新生成表。任意缩放矩形按行计算8种抖色相位并平铺。圆环保留原ARGB8888素材、A8柔影与字体透明/抗锯齿能力，最终由LVGL直接混合到565。

`lvgl_port.c`采用两个480×32×2=30720B局部缓冲，总61440B普通SRAM；CPU绘B时DMA发A。`GUI_DRAW_BUFFER_ROWS`用于明确行数，全屏一个脏区10次DMA。PARTIAL仍只发送变化区域，大缓冲不强制整屏刷新。flush仅一次原地换序/必要的stride紧密化，每块一次连续DMA，无逐行中转。SPI Start/Wait由同一GUI任务成对执行，中断仅通知；完成核DMA EN/SPI BSY，尾块主动收尾CS/锁，错误安全中止后在任务阶段限速完整重绘。最后缓冲可用才通知LVGL，DMA源地址检查拒绝CCM。旧const小端同步LCD接口仍保留兼容，已退出LVGL链路。

`dashboard_ui.c`缓存当前段8条记录的文字及对应结论/模式，滚动不重复格式化；新测量在历史打开时完成，静止时立即更新，滑入中在安全终点更新并保留滚动位置。`measurement_page_pause_presentation`只合并底图显示，真实会话/进度/完成/超时/模型继续运行。返回在同一次GUI调用内取消未完成的滑入、停止列表惯性，恢复原导航、同步最新轮廓/结果/统计/按钮；随后隐藏菜单，在隐藏期间设X480并update_layout完成坐标复位，最后归还输入。复位无动画、不会因显示旧X0坐标而额外刷新菜单；不主动调用阻塞整屏刷新。进入函数/180ms曲线保持，重开同一设置菜单仍复用六行，从屏外正常滑入。透明输入层只在菜单/入场期间拦截，主题保持。

`ui_underlay_begin`仅在已知不透明、无圆角的菜单完全遮住当前自绘裁剪框右侧/高度时生效；几何/结果卡只合成露出部分，包装函数返回后恢复原clip，不影响菜单或兄弟控件。无有效遮挡时完全沿原绘图路径。未用最终合成整页缓存，也没有实现5.17候选的纯色块跳过发送。

52KiB LVGL池放独占`.lvgl_ccm (NOLOAD)`，由`GUI_LVGL_PoolAlloc`开CCM数据时钟并清零；当前启动汇编未泛化处理CCM，不能随意在通用.ccmram放初始化变量。只有CPU的软件绘图/解码可用此池，DMA必须读显式普通SRAM输出。RTOS堆24KiB、GUI栈8KiB未缩减。无整屏缓存，SPI/触摸/时钟/引脚/液晶寄存器未变。565多层透明边缘与纯色量化并非与旧888逐像素相同，敏感静态渐变已局部抖色；仍须面板同条件比较。

当前重点复用历史文字、固定渐变与时钟小脏区；未增加整菜单/8条记录的像素缓存。板载W25Q128适合素材/参数/记录存储，不能扩充绘图RAM，且与LCD共SPI1，读写须仲裁；片内Flash余315208B，本轮未接外部Flash。普通SRAM链接余30512B不等于实时堆余量，保留给运行时、通信和测量。

当前仍是模拟相机（包括32.00×20.00mm矩形像素角点→固定映射→尺寸路径），不是MaixCAM2真实测量。`gui_camera_config.h`集中放固定参数，目前仅适配模拟夹具；真实安装需一次性替换。界面没有现场标定向导。

`GUI_AppInit(NULL)`为仅内存存储，重启清空；没有RTC时显示开机时间，不冒充参考图日期。`GUI_AppSetNetwork`绑定非阻塞扫描/连接/断开请求，true只表示受理，只有`GUI_AppNetworkStatus`后端回报才变为已连接。这些接口和新增`GUI_AppNetworkUpdate`只在GUI任务调用，Camera任务经静态快照队列转交。网络现已绑定相机协议但实际双板待验，Flash仍未接持久化；存储模型布局新增了公差/结论/时间/统计，后续Flash后端必须做版本化，不能原样载入旧结构。

## H6触摸驱动（2026-10-18用户确认实机验收通过）

- `User/Hardware/FT6336U.c/.h`：PE1拉低20ms后释放，再等待至少300ms；

  主要依据用户提供的[商家ctp.c](<D:/.Data/spi 3.5寸屏幕资料/CL35BC1070-40A_CTP/测试程序/STM32F1_ST7796_IPS_4SPI_CTP Demo_V1/HARDWARE/TOUCH/ctp.c>)，
  并核对同包STC32_4SPI版本，初始化与CONTACT规则一致。
- 按商家顺序先读0x02点数1字节，再读0x03～0x06的坐标4字节，两次HAL事务共用一把锁。
  本工程只支持单指N1，多指松手；不扫第二槽，不再跨帧跟踪编号。
  **仅(XH & 0xF0)==0x80的CONTACT有效**，初始DOWN、UP均不更新界面位置。
  按商家忽略原始双零；单轴0仍合法，不裁边或把0移到按钮。
  坐标只做原有横屏交换/镜像，直接交给LVGL，不再做中值/边缘确认/短按补交/圆点余辉。
  通信超时/非法数据仍松手；连续3次通信失败后每秒尝试重新配置，
  不反复复位触摸芯片；共用I²C控制器的故障统一由下述总线层处理。
- `User/Hardware/I2C2_Bus.c/.h`：main先完成OLED启动检测、HAL延时及刷新，
  再创建静态互斥锁和其他RTOS对象并启动调度器。调度前只有main，通信不需要锁，
  也不要求提前创建锁；任务期OLED每条命令/每页数据与触摸每次传输共用同一把锁。
  锁覆盖HAL事务、错误码读取及必要的故障恢复；触摸芯片复位延时、整个OLED_Update不持锁。
  取锁等待约25ms、触摸HAL传输超时20ms，均为配置值而非实测耗时。
  2026-10-18补充：HAL传输返回忙/超时等故障时，每秒最多一次，在原锁内关闭/复位I²C2、
  开漏释放PB10/PB11，必要时补最多9个数据时钟、产生STOP，再恢复AF4和原100kHz配置。
  SCL持续低、SDA未释放或重新初始化失败均有限退出；不把失败帧重试成有效点击。
  单纯设备不应答、取锁失败不重置总线，启动调度器前不执行RTOS延时恢复。
