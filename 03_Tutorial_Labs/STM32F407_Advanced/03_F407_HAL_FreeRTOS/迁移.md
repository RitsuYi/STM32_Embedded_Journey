# MSPM0 小车模块迁移到 STM32F407 HAL + FreeRTOS 方案

编写日期：2026-09-19。本文是根据本地工程扫描形成的实施方案；本次只创建本文档，尚未修改 `.ioc`、生成外设代码或移植业务代码，尚未进行实机验证。

### 1.2 必须遵守的顺序

**核对接线与资源 → CubeMX 初始化引脚、时钟、外设和 NVIC → 生成并编译基础工程 → 编写 BSP → 移植设备及协议 → 接入控制与任务 → 实机验收。**

1. 每增加一个硬件模块，先更新当前 `.ioc`，生成相应 `MX_*_Init()`，然后编写该模块的代码。
2. 引脚复用、GPIO 初始电平、PWM 基础参数、UART 波特率、SPI 模式、ADC 通道与 NVIC 由 CubeMX 维护；BSP 使用生成的句柄启动、停止和操作外设。
3. 保留目标工程已手动接入的 FreeRTOS，统一使用原生 API；CubeMX 本轮只管理 HAL 硬件配置，不再生成第二套 FreeRTOS/CMSIS-RTOS。
4. 先达到源项目默认功能的等价行为，再优化 DMA、硬件编码器和任务拆分，避免同时改变接线、计数单位和控制参数。
5. 当前 `Core/Inc/FreeRTOSConfig.h` 已有未提交修改。实施时在现有内容上核对修改，不覆盖用户改动。
6. 只按阶段新增和接入必需文件。遵守当前目录规则：禁止批量删除文件或目录；需要批量清理时由用户手动操作。

## 2. 扫描结论：迁移前必须理解的差异

### 2.1 源工程实际运行结构

源工程虽然包含 FreeRTOS 源码，但 `CMakePresets.json` 的 Debug/Release 默认均为 `USE_FREERTOS=OFF`，`user/main/main.c` 也没有创建 RTOS 任务。实际入口是：

```text
Board_InitSafe()
  → App_Init()
  → AppTime_Init()
  → while (1): App_Run() + AppTime_RunPendingTasks()
```

`user/timer/app_time.c` 使用 TIMG12 的 1 ms 中断累计软件时钟并发布待执行计数，主循环每 20 ms 调用车控、模式 4、钢球控制，显示服务也是 20 ms。因此本次包含两项工作：MSPM0 DriverLib 到 STM32 HAL 的硬件适配，以及裸机调度到 FreeRTOS 的并发改造。不能把 `app_task.c` 的名称理解成已有 RTOS 任务。

| 源工程模块/行为 | 已确认的当前配置 | 对迁移的影响 |
| --- | --- | --- |
| 两轮差速驱动 | TIMG6 双通道 10 kHz PWM；四根方向线；逻辑命令范围 `-1000～1000` | 换算到目标 ARR，保持命令接口和停止行为 |
| 电机驱动使能 | 源 PCB 的 D153B STBY 硬接 3.3 V，没有 STBY GPIO | 不能凭空增加软件 STBY 引脚；上电必须保持 PWM=0、方向线为低 |
| 左右编码器 | A 相双边沿中断、B 相判向；`13 × 2 × 28 = 728 count/rev` | 首轮保留 2 倍频，否则转速和距离阈值都会改变 |
| 灰度循迹 | 八路数字输入；权重 `+7,+5,+3,+1,-1,-3,-5,-7` | 保持 OUT1～OUT8 顺序及误差正方向 |
| 摆杆舵机 | 50 Hz；安全范围 1000～2000 μs；水平 1400 μs | 这些是现车机械标定，先保留再实测；不能默认水平为 1500 μs |
| 钢球执行机构 | 默认 `BOARD_BALL_ACTUATOR_SERVO`，另有 ZDT 步进后端 | 默认先迁舵机，步进作为独立可选阶段 |
| 视觉 | UART3，115200，`BALL,<position>\r\n`，位置单位 cm | 保持严格格式、范围、帧代际和 200 ms 超时 |
| 航向 | UART1，115200；TIgryo 9 字节帧解码 | 保留解码器，替换串口传输与快照同步 |
| 控制串口 | UART0；默认 HC-04 9600 文本协议；可切 ESP32 115200 Dashboard | 波特率和协议必须成对切换，同一端口只能绑定一个后端 |
| SPI 与屏幕 | SPI1，模式 0、8 bit、4 MHz；SH1107 OLED 与 BMI270 共用 | STM32 可改用 SPI2，但必须保持器件协议和独立片选 |
| BMI270 | `BOARD_BMI270_ENABLE=0`，串口陀螺仪为启用状态 | 首轮不把 BMI270 当成默认必需设备 |
| 电池检测 | ADC0/PA25，12 bit；逻辑混在 `display/app_display.c` | 抽成独立 Battery 模块，停止依赖显示刷新 |
| 业务控制 | 速度 PID、航向、循迹、MODE 2/3/4、钢球定点、D 模式、自动整定 | 先保留行为，再按职责拆分大文件 |

### 2.2 STM32 目标工程现状

| 项目 | 当前值/证据 | 处理建议 |
| --- | --- | --- |
| 芯片 | `.ioc`：STM32F407VGT6、LQFP100 | 以下引脚候选以此封装为前提 |
| 时钟 | HSE 8 MHz；SYSCLK 168 MHz；APB1 42 MHz；APB2 84 MHz | 保留，先确认实际板载晶振 |
| 已有引脚 | USART1 PA9/PA10；LED1 PB2；LED3 PB6；SWD PA13/PA14 | 保留调试串口与已有 LED |
| HAL 时基 | TIM6，1 ms，`stm32f4xx_hal_timebase_tim.c` | TIM6 专用，不分配给小车控制或 PWM |
| RTOS 内核 | `FreeRTOS/INC/task.h` 标注 V11.1.0；顶层 CMake 手动加入 `heap_4.c`、`port.c` 等 | 保留当前内核与 Cortex-M4F 端口，不复制源项目 M0+ 端口 |
| 异常入口 | `startup_stm32f407xx.s` 直接指向 `vPortSVCHandler`、`xPortPendSVHandler`、`xPortSysTickHandler` | 当前路由已存在；每次 CubeMX 生成后检查是否保留 |
| Core 中异常函数 | `stm32f4xx_it.c` 内 SVC/PendSV/SysTick 函数为空 | 当前向量直接路由到 port，因此不能仅据空函数判定调度未接入 |
| RTOS 参数 | tick=100 Hz；堆=4096 B；优先级数量=5；软件定时器任务优先级=4 | 扩展任务前调整 tick、内存预算及优先级 |
| 已有应用 | `main.c` 中两个 LED 任务；未检查 `xTaskCreate()` 返回值 | 先补齐创建失败处理，再逐步替换为应用入口 |
| 内存布局 | 链接脚本：普通 RAM 128 KB、CCMRAM 64 KB、Flash 1 MB | 分开预算；DMA 缓冲区使用 DMA 可访问的普通 SRAM |
| 编译 | C11、CMake/Ninja、Cortex-M4、`fpv4-sp-d16`、hard float | 所有移植源文件重新编译，不混入旧 `.o/.a` |
| 工程说明 | 当前 README 仍以串口入门工程为主；`ST迁移.md` 是工具链操作备忘 | 完成迁移后更新 README；本方案独立放在 `迁移.md` |

`.ioc` 的 PLLQ 当前为 4，对应 84 MHz 的相关时钟输出。本轮不启用 USB/SDIO/RNG；以后使用这些外设时，重新检查其时钟要求，不把当前配置视为已满足 48 MHz 外设需求。

## 3. 模块分层与目录规范

### 3.1 依赖关系

```text
App                 任务、模式、命令执行、启动顺序、故障策略
 ├─ Control         车控、航向、循迹、钢球、PID
 ├─ Protocol        字节协议解析/组帧，输出数据与命令
 └─ Devices         电机、编码器、舵机、传感器、显示等设备接口
       └─ BSP       HAL 句柄映射、GPIO/PWM/UART/SPI/ADC 访问
             └─ Core + Drivers   CubeMX 生成代码和 ST HAL/CMSIS

Common              数据类型、单位约定、运行参数；不得依赖上层
Platform            时间、同步、日志、HAL 回调分发、RTOS 钩子
FreeRTOS            保留目标工程现有内核
```

协议层只解析和编码，不能直接调用 `Motor_SetBoth()` 或切换模式。控制层通过设备接口输出，不包含 `stm32f4xx_hal.h`。BSP 不包含 PID、业务模式或协议代码。任务和模块不是一一对应：PID、按键驱动、编码器各自独立成模块，但不必各建一个任务。

## 4. 先在 CubeMX 完成引脚与外设初始化

### 4.1 接线前提与候选资源表

| HSE | 源板不同 | PH0 / PH1 | RCC→Crystal/Ceramic Resonator，8 MHz |

资源约束：PB6 已接目标 LED，因此电机 PWM 选 PD12/PD13；不要再用 PB6 的 TIM4_CH1 复用。SPI2 采用软件片选，不启用硬件 NSS。灰度 PE0～PE7 只轮询，不打开 EXTI，避免与编码器 EXTI0/6 争用线路。不开启 FSMC、SDIO、以太网等会占用本表引脚的功能。板卡确有冲突时，先在 CubeMX 改映射再同步接线表。

电气核对只需围绕实际接线：编码器/灰度输出电平与输出类型、3.3 V UART、ADC 分压上限、模块共地，以及电机/舵机电源。电池不能直接接 PC0；原分压比必须按实际电阻确认。

### 4.2 CubeMX 操作顺序

1. 打开**当前工程** `03_F407_HAL_FreeRTOS.ioc`，确认 STM32F407VGT6 / LQFP100 和工程输出路径正确。
2. Project Manager 使用 CMake；Code Generator 保留 `Keep User Code when re-generating`，外设初始化按 `.c/.h` 分文件生成。检查当前 `ProjectManager.DeletePrevious=true` 对应设置，取消自动删除旧生成文件的选项，避免生成过程进行未经核对的批量清理。
3. SYS 选择 Serial Wire、Timebase Source=TIM6；保留现有 HSE/PLL 和总线分频。不在 Middleware 中新增 FreeRTOS。
4. 先配已有 LED、调试 UART 和安全 GPIO，设置四根电机方向线 Low、两根 SPI CS High、蜂鸣器 High，Generate Code 后编译并验证 LED/串口。
5. 按阶段增加 USART2/3、UART4，全部 Asynchronous、8N1、无流控。USART2 在首轮配置 9600，其余 115200；打开各 UART global interrupt。
6. 增加 SPI2、OLED 控制 GPIO，配置见下一节；编译验证后再编写共享总线及 OLED 驱动。
7. 增加 TIM4 两路 PWM、编码器 GPIO/EXTI；先验证波形和计数，才接入 Motor/Encoder 和速度闭环。
8. 增加灰度 Input、按键 Input、ADC1；验证输入位序、按键电平与电压换算。
9. 增加 TIM1 舵机 PWM；确认安全位置与范围后接入钢球控制。UART5/BMI270 按可选阶段配置启用。
10. NVIC 使用 `NVIC_PRIORITYGROUP_4`。会调用 FreeRTOS `FromISR` API 的 UART/EXTI/DMA 中断设抢占优先级 6、子优先级 0；SysTick/PendSV 保持最低级 15；TIM6 保留现有 15，回调只维护 HAL tick。
11. 每次生成后检查 `gpio.c` 初始输出顺序、`main.h` 标签、MSP 引脚、`stm32f4xx_it.c` 的 HAL IRQ 调用、CMake 新增 HAL 源文件和启动向量，再编译。只在这些检查完成后编写模块。

在当前 4 位 NVIC 优先级和阈值 5 的设计下，数值 0～4 的 ISR 不调用 FreeRTOS API；数值 5～15 可使用允许的 `FromISR` API。不要把已左移的 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 直接传给 `HAL_NVIC_SetPriority()`。规则参考 [FreeRTOS Cortex-M 中断优先级说明](https://www.freertos.org/Documentation/02-Kernel/03-Supported-devices/04-Demos/ARM-Cortex/RTOS-Cortex-M3-M4)。

### 4.3 定时器、SPI、ADC 的具体起始配置

以下为实施起始值，基于当前时钟树；CubeMX Clock Configuration 中的实际 timer clock 是最终计算依据。

| 外设 | CubeMX 设置 | 编写驱动时的约束 |
| --- | --- | --- |
| TIM4 电机 | APB1 timer clock=84 MHz；PSC=0、ARR=8399；CH1/CH2 PWM mode 1、极性 High、Pulse=0 | `84 MHz / (1 × 8400) = 10 kHz`；保持逻辑 0～1000，CCR 按 8400 比例换算 |
| TIM1 舵机 | timer clock=168 MHz；PSC=167、ARR=19999；CH1 PWM mode 1、极性 High；初始 Pulse=1400 | 计数单位 1 μs，周期 20 ms；明确允许后才 `HAL_TIM_PWM_Start()` |
| 编码器首轮 | A 相 Rising/Falling EXTI；B 相 GPIO Input | 两路保留 2 倍频和 728 count/rev；上下拉依据编码器输出电路选择 |
| TIM2/TIM3 后续可选 | 左 PA0/PA1→TIM2_CH1/2，右 PA6/PA7→TIM3_CH1/2 | 仅硬件编码器阶段启用，必须同时关闭对应 EXTI 计数 |
| SPI2 | Master、Full Duplex、8 bit、MSB first、CPOL Low、CPHA 1 Edge、Software NSS、分频 16 | PCLK1=42 MHz 时 SCK=2.625 MHz，低于源 4 MHz；先验证可靠性，不假定可精确配出 4 MHz |
| ADC1 | PC0/IN10、12 bit、Right alignment、单通道、Software start、非连续；PCLK2/4=21 MHz；采样时间先选 144 cycles | 每 50 ms 触发采样；采样时间随后按分压阻抗与误差实测调整 |
| TIM6 | 保留 HAL 自动生成的 1 ms 配置 | 不停止、不重新用作控制调度 |

PWM 换算必须重新实现：源舵机 `Servo_PulseUsToCompare()` 返回 `pulse_us - 1`，不能照搬到上述 STM32 向上计数 PWM1 配置；此处 CCR 应表达期望高电平的微秒数。源电机计数周期 4000 也不能写死带入目标驱动。驱动设置 CCR 后仍需用示波器验证 0%、中间占空比和最大占空比。

### 4.4 UART/DMA 分两步完成

首轮先使用 HAL 中断收发与独立环形缓冲，验证业务和恢复逻辑。后续确有吞吐或 CPU 占用需求时，再在 CubeMX 增加 DMA：

- 高频视觉/陀螺仪 RX 可采用 Circular DMA + IDLE；当前目标 HAL 声明了 `HAL_UARTEx_ReceiveToIdle_DMA()`。
- CubeMX 中逐一记录 UART RX/TX 的 DMA controller、stream、channel、方向和 NVIC；STM32F4 同一 stream 不能同时分配给两个活动请求。SPI/ADC 若也启用 DMA，要一起核对资源表。
- DMA 缓冲区放普通 SRAM，不能放 `0x10000000` 的 CCM。按目标 DMA 对齐要求配置；当前芯片无需引入其他带 D-cache MCU 的缓存维护代码。
- IDLE 是传输事件，不等于完整业务帧；处理半传输、完成和回绕位置，按新增字节数消费，防止同一批字节重复解析。
- 回调发布长度/位置或通知，任务解析；缓冲区使用前确认生命周期，不把任务栈上的临时数组交给未完成的 DMA。

## 6. FreeRTOS 改造与数据归属

### 6.1 配置起始建议

| 配置 | 目标起始建议 | 原因/验证方式 |
| --- | --- | --- |
| `configTICK_RATE_HZ` | 1000 | 与源 1 ms 时间语义对齐，支持 5/20/50 ms 周期 |
| `configMAX_PRIORITIES` | 8 | 可用 0～7，按下表分配 |
| `configTOTAL_HEAP_SIZE` | 先预算 32 KB | 不是最终保证值；根据任务栈、队列、stream buffer 和运行水位调整 |
| 内存分配 | 保留 `heap_4`，初始化阶段集中创建 | 工作循环不反复 malloc/free；逐项检查创建结果 |
| `configCHECK_FOR_STACK_OVERFLOW` | 保留 2 | 合并栈溢出钩子，触发时关闭可直接关闭的输出 |
| `configUSE_MALLOC_FAILED_HOOK` | 设 1 并实现钩子 | 创建失败可定位，禁止带缺失资源进入运行 |
| 栈/堆水位 | 开启 `INCLUDE_uxTaskGetStackHighWaterMark`，记录最小剩余堆 | 覆盖浮点、格式化输出和异常路径后确定余量 |
| NVIC 阈值 | `configPRIO_BITS=__NVIC_PRIO_BITS`；逻辑阈值 5，最低 15 | 以当前 M4F port 读取的宏为准，移位只在配置宏中做一次 |
| 软件定时器任务 | 建议明确设为 2 | 当前宏是 `configMAX_PRIORITIES-1`，增加优先级数会连带升高它；回调保持短小 |
| 配置清理 | 逐项核对 MPU/TrustZone/MVE 等模板宏 | F407 的 GCC M4F 端口不因模板宏就拥有这些硬件能力；按实际端口需要保留/整理 |

`xTaskCreate()` 的栈深度在当前 Cortex-M4 端口按 `StackType_t` 元素计，1 word=4 B；不要把 512 words 误当成 512 B。32 KB RTOS 堆与链接脚本 `_Min_Heap_Size=0x200` 是两个不同预算，修改后者不会扩大 `heap_4` 的堆。

### 6.2 推荐任务划分

先实现一个保持原调用顺序的 AppTask 过渡版本，所有业务状态仍由它独占。驱动单测通过后，再在同一改造阶段引入下表任务和命令/快照接口，不能先拆任务再补同步。

| 任务 | 周期/唤醒 | 优先级 | 初始栈估算 | 职责与限制 |
| --- | --- | --- | --- | --- |
| InitTask，临时 | 启动时一次 | 6 | 768 words | 初始化设备、建立就绪状态，完成后退出；不得等待外部数据直到永远 |
| ControlTask | `xTaskDelayUntil`，20 ms | 5 | 1024 words | 执行命令、读取传感器快照、模式/车控/钢球计算、输出；独占运动状态 |
| CommTask | RX 通知唤醒，最长约 5 ms 检查超时 | 4 | 1024 words | 轮流消费各端口有限批次字节，协议解析、发布命令/传感器快照、遥测组帧 |
| MonitorTask | 10 ms 服务，50 ms 电池采样 | 3 | 512 words | 监控心跳、电池、故障和堆栈水位；ADC 使用异步或有限等待 |
| InputTask | 5 ms | 2 | 384 words | 按键消抖、菜单事件、蜂鸣节奏；只发布命令 |
| DisplayTask | 首轮 20 ms 服务，可降低实际刷屏频率 | 1 | 768 words | 只读一致快照，独占 OLED；传输失败可降级 |
| LogTask，可选 | 队列唤醒 | 1 | 512 words | 调试 USART1 输出与日志限流，不能阻塞控制任务 |

常驻任务初始栈约 16.5 KB，另加 InitTask 临时栈、TCB、队列、环形缓冲及 RTOS 内部对象。按实际分配方式和链接 map 核算，不要把这些估算当成测得的内存用量。复杂格式化输出只放低优先级任务，并重新测栈水位。

保留原先周期调用顺序：在 20 ms 更新边界附近完成命令/模式处理，然后 `CarControl_Update20ms()` → `Mode4Control_Update20ms()` → `BallBalance_Update20ms()`。首轮避免将相互作用的车控和球控分到同优先级独立任务中。之后若改顺序，必须验证 MODE 4 的当周期/下一周期目标关系。

启动接线顺序：`HAL_Init()` → 系统时钟 → 所有已配置的 `MX_*_Init()` → 强制安全输出 → 在 main 的 USER CODE 区调用应用资源创建函数 → 检查所有队列、锁和任务创建结果 → `vTaskStartScheduler()`。InitTask 在调度启动后初始化设备和业务状态，再发布就绪事件；其他任务先等待各自所需的就绪位，不依靠 InitTask 优先级较高来假定初始化已经完成。

通信资源就绪后即可开放状态查询与 STOP；运动许可需额外满足 Motor/Encoder/Control 就绪，传感器相关模式还要检查数据新鲜度。UART 接收中断启用前建立缓冲区及回调上下文，若通知目标尚未创建，则只缓冲字节、不调用无效任务句柄。资源创建失败或调度器返回时进入明确的安全故障分支，不落入空主循环而失去诊断。

### 6.3 队列、快照与总线所有权

| 数据/资源 | 写入者 | 读取者 | 推荐方式 |
| --- | --- | --- | --- |
| 普通业务命令 | CommTask、InputTask | ControlTask | 长度先取 16 的有界 `CommandQueue`，按结构体复制，含命令类型、来源和序号 |
| STOP/故障请求 | 输入、通信、监控模块 | ControlTask | 独立锁存标志/通知，不依赖可能已满的普通队列；STOP 使旧运动命令失效 |
| 视觉/航向快照 | CommTask | ControlTask | 每种传感器独立的长度 1 最新值队列；发布完整结构，包含时间戳、有效位、generation |
| 系统状态快照 | ControlTask | DisplayTask、CommTask | 一个快照副本加短临界区或 mutex；读者复制后立即解锁；不要用同一消费队列争抢状态 |
| 电池快照 | MonitorTask | ControlTask、DisplayTask | 独立副本和短同步，含有效位及采样时间 |
| UART RX | UART ISR/DMA | CommTask | 每端口独立环形缓冲；若用 StreamBuffer，满足单生产者/单消费者约束 |
| UART TX | 业务提交，UART 服务启动发送 | ISR/DMA 完成通知 | 每端口串行化完整帧；缓冲区所有权持续到发送完成，不允许多任务字节交错 |
| SPI2 | OLED/BMI270 请求者 | 对应设备 | 一个 mutex 保护完整 CS 有效事务，超时也释放 CS 与锁 |
| Motor/Servo/模式内部状态 | ControlTask | 状态快照消费者 | 普通运行仅一个写入者；故障硬停是受控例外 |

移植源 `__disable_irq()` 时逐处判断用途。只复制几字节状态可用很短的临界区；保护 SPI 整笔传输必须用 mutex；控制状态尽量消除多写入者。`volatile` 不能保证多字段快照一致，也不能代替互斥。不能在关中断区域中等待串口、SPI、延时或运行 PID。

### 6.4 时间与中断边界

- 业务时间全部从 `PlatformTime_NowMs()` 获取。调度开始后使用 RTOS tick 换算；只有启动前的 HAL 初始化使用 HAL 毫秒时基。所有业务超时状态在调度启动后初始化，避免时基切换出现时间倒退。
- 用无符号差值 `(uint32_t)(now - last)` 判断超时，覆盖 32 位毫秒计数回绕；函数声明中写清单位。
- 20 ms 控制使用 `xTaskDelayUntil()`；若发现超过截止时间，记录超期并重建下一次基准，不连续补跑多个固定 dt 控制迭代。根据严重程度停止输出，避免零时间间隔积分和速度估算失真。
- IRQ 内只做硬件服务、字节搬运、编码器计数、通知。调用 RTOS 时使用 `FromISR` 版本并根据唤醒结果请求切换。
- `stm32f4xx_it.c` 保留 CubeMX 生成的 `HAL_UART_IRQHandler()` / `HAL_GPIO_EXTI_IRQHandler()` / DMA IRQ 入口；设备分发放 `Platform/hal_callbacks.c`。
- 每一种 HAL 弱回调只提供一个强实现，按句柄/引脚分发。现有 `HAL_TIM_PeriodElapsedCallback()` 位于 main.c 且负责 `HAL_IncTick()`；首轮保留它，通过 USER CODE 委托其他逻辑，不在新文件重复定义。
- 当前启动文件采用直接向量路由，首轮保留。生成后核验 `.isr_vector` 对应槽位，而不只是检查函数存在；若以后采用配置宏别名方案，必须同时避免 Core 中生成的同名强符号冲突。

## 7. 易错模块的专项处理

### 7.1 编码器计数与距离单位

首轮采用 EXTI A 相双边沿，实现与原项目一致的 728 count/rev。左右安装方向先沿用源值并人工转轮确认；正向行驶时上层累计值和 RPM 的正方向一致。

后续改 TIM2/TIM3 Encoder mode TI12 的 4 倍频时，单独立项验证：

1. 期望输出轴每圈变为 `13 × 4 × 28 = 1456 count/rev`；同时调整计数断言、RPM 换算和诊断解释。
2. 源 MODE 2 停车阈值 23000 pulses、MODE 4 的 5133 pulses 等都是旧计数单位。若直接暴露新计数，相同距离分别应按比例变为 46000、10266；扫描并统一转换所有脉冲阈值。
3. 更长期建议上层使用毫米/输出轴转数，或由 Encoder 层提供明确的旧单位兼容接口；不能部分模块用 728、部分模块用 1456。
4. 自由运行读取计数差值，处理位宽和回绕；TIM3 是 16 位计数器，需保证相邻采样间位移低于半量程。读取后清零会有边界丢计数风险，应优先做连续计数差分。
5. 软件扩展累计计数时明确溢出行为，避免有符号整数溢出。取消原 A 相中断次数指标的旧语义，重新说明硬件模式诊断值。

### 7.2 视觉、陀螺仪与控制协议兼容

- 视觉只接受规范的 `BALL,-1.00\r\n` 等数据：范围 -12.00～12.00 cm、恰好两位小数、可选负号、允许 LF/CRLF。保留对额外字段、空格、`+`、NaN、Inf、溢出和非规范前导零的拒绝规则。`BALL,-1.00` 是合法位置，不是丢球标记。
- 无新合法帧达到 200 ms 时置无效/离线，保留最后位置供诊断；不能用重复快照刷新时间戳。保持 generation 对新帧的区分，显示读取不能消费控制需要的新帧。
- TIgryo 保留 9 字节帧、CRC、角度单位、归一化和控制数据新鲜度规则。200 ms 的视觉超时不能拿来替换陀螺仪 100 ms 控制阈值。
- Dashboard Binary V1 保持 `AA 55` 帧头、版本、长度、CRC 和字节序；HC-04 保持命令大小写、字段数量、模式返回与调参响应。
- UART 错误覆盖 ORE/FE/NE、环形缓冲溢出、半帧、连续帧、错误帧后恢复。遇到失步清理解析状态，重启 HAL 接收并记录计数。
- USART1 调试输出独立，禁止把 `printf` 文本混入视觉、陀螺仪、Dashboard 或步进电机协议口。

### 7.3 SPI、显示和电池

OLED 的 DC 电平切换、片选、命令/数据发送属于一个受保护的访问序列；两个设备不能同时片选。设备初始化和恢复也必须遵守同一锁规则。首次从 4 MHz 降到 2.625 MHz 后重新测刷新耗时，按需分块/按页刷新；不要持锁等待下一个显示周期。

电池模块负责采样、滤波、量纲转换、有效性与低压状态，显示仅读取。转换公式为 `Vbat = raw / 4095 × Vref × 分压系数`。源配置中 3300 mV 对应整包满量程 36300 mV，等效分压系数 11；这只是旧板配置，必须按 STM32 实际分压电阻和参考电压重新确认。保留 50 ms 采样、滤波和原告警行为并校准，未获得合法采样时不得把默认零值当成真实电压。

### 7.4 运动与故障状态

初始化阶段电机 PWM=0、方向脚 Low、蜂鸣器静音；舵机在完成配置和安全位确认后才启用。OLED/BMI270 缺失按可选设备降级，视觉或陀螺仪缺失则禁止依赖该传感器的模式，不能无限等待导致系统无法响应 STOP。

普通运行由 ControlTask 处理 STOP 并清理旧命令、PID 状态和执行机构目标。检测到严重故障时，预先可用的最小硬停函数直接归零本地电机 PWM；不能在中断已关闭的钩子里调用 UART 等待、mutex 或 `HAL_Delay()`。舵机故障姿态必须依据机械结构规定为回水平或停止脉冲。步进电机是外部控制器，仅 MCU 复位不能保证外部停止，需验证驱动器超时停止或独立使能策略。

后期引入 IWDG 时，由监控模块确认关键任务心跳均更新后喂狗；不要让任意一个任务单独循环喂狗掩盖控制任务卡死。

## 8. CMake 与 CubeMX 再生成的维护方式

1. 保留根目录的工程名、启动文件、链接脚本、目标内核清单和工具链设置。
2. 在顶层现有 `add_subdirectory(cmake/stm32cubemx)` 之后加入 `add_subdirectory(Application)`。
3. `Application/CMakeLists.txt` 按模块显式列源文件；可选模块用构建条件控制。不要递归扫描整个源工程，避免把旧 main、TI 驱动和两套内核编进目标。
4. 自写文件列表和 include 路径不要手工放进 `cmake/stm32cubemx/CMakeLists.txt`；该文件用于接收 CubeMX 外设配置变化。
5. 可以只导出 `Application` 为自写 include 根目录，例如 `#include "Devices/Motor/motor.h"`；新文件不再沿用到处添加小目录的 include 配置。

起步构建片段示例，只有列出的文件真实创建后才加入：

```cmake
# 根 CMakeLists.txt，CubeMX 子目录之后
add_subdirectory(Application)

# Application/CMakeLists.txt
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/App/app_main.c
    ${CMAKE_CURRENT_SOURCE_DIR}/App/app_tasks.c
    ${CMAKE_CURRENT_SOURCE_DIR}/BSP/board.c
    ${CMAKE_CURRENT_SOURCE_DIR}/Platform/platform_time.c
)
target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}
)
```

常规编译复用当前预设，不复制源项目绝对工具链路径：

```powershell
cmake --preset debug-armgcc
cmake --build --preset build-debug
cmake --preset release-armgcc
cmake --build --preset build-release
```

每次 CubeMX 再生成后，检查：启动向量仍路由到 FreeRTOS、TIM6 HAL tick 仍存在、main USER CODE 的应用入口仍在、FreeRTOSConfig 用户配置未覆盖、CMake 内核只有一份、新增外设的 HAL 源文件已加入、GPIO 初始状态未变化。迁移完成前做一次“重新 Generate Code 后再次编译和启动”的验收。
